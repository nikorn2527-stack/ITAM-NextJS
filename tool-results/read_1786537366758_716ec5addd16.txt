   231→## 4. ระบบสิทธิ์และความปลอดภัย (RBAC)
   232→
   233→### 5 Roles
   234→| Role | ชื่อแสดง | สิทธิ์หลัก |
   235→|------|----------|-----------|
   236→| `superadmin` | ผู้ดูแลสูงสุด | ทุกอย่าง + จัดการ Admin คนอื่น |
   237→| `admin` | ผู้ดูแลระบบ | ทุกอย่าง ยกเว้นจัดการ Super Admin |
   238→| `editor` | เจ้าหน้าที่จัดการข้อมูล | ดู/เพิ่ม/แก้ไข/ย้าย/จดมิเตอร์/Export |
   239→| `meter` | ผู้จดมิเตอร์ | ดูอุปกรณ์ + จดมิเตอร์ + Print |
   240→| `viewer` | ผู้ดูรายงาน | ดูข้อมูล + Dashboard + Print |
   241→
   242→### Permissions (12 ตัว)
   243→```
   244→VIEW_DASHBOARD, VIEW_DEVICES, VIEW_ANALYTICS,
   245→METER_WRITE, DEVICE_EDIT, DEVICE_DELETE,
   246→DEVICE_TRANSFER, LIFECYCLE_EDIT, MASTER_DATA_EDIT,
   247→EXPORT_PRINT, PRINT, ADMIN
   248→```
   249→
   250→### วิธี Login (2 ช่องทาง)
   251→1. **Google Session** — Login ผ่าน Google Account (ถ้า deploy แบบ USER_DEPLOYING)
   252→2. **Username/Password** — Login ผ่านฟอร์ม (SHA-256 + salt hash)
   253→
   254→### ความปลอดภัย
   255→- ✅ Password hashing: SHA-256 + salt (per-user salt)
   256→- ✅ Rate limiting: 5 ครั้งผิด → lockout 5 นาที
   257→- ✅ Auth token: UUID + CacheService (TTL 6 ชั่วโมง)
   258→- ✅ Row-level security: `Allowed_Sites` จำกัดการเห็นข้อมูลตาม Site
   259→- ✅ "Last admin" protection: กันปิด admin คนสุดท้าย
   260→- ✅ Audit Log: บันทึกทุกการกระทำสำคัญ
   261→
   262→### Site-based Row-level Security
   263→ครอบคลุม:
   264→- รายการอุปกรณ์ (All_Devices)
   265→- ประวัติการย้าย (Location_History)
   266→- ประวัติมิเตอร์ (Meter_Readings)
   267→- ตัวเลือก Dropdown (Master_Data)
   268→- ผลลัพธ์ Paper Analytics และ Dashboard

   272→## 5. ฟีเจอร์หลัก 7 หน้า
   273→
   274→### 5.1 Dashboard
   275→- สรุปจำนวนอุปกรณ์ทั้งหมด / ติดตั้งแล้ว / ไม่ใช้งาน
   276→- จำนวนแผ่นกระดาษเดือนล่าสุด + % เปลี่ยนแปลง MoM
   277→- Breakdown ตามประเภท / สถานะ / อาคาร (Top 10) — คลิกเจาะดูรายการ
   278→- กราฟการใช้กระดาษแยกหน่วยงาน, อาคาร/ชั้น, แนวโน้มรายเดือน
   279→- Smart Insights สรุปจุดผิดปกติอัตโนมัติ
   280→
   281→### 5.2 จัดการอุปกรณ์ (Device Management)
   282→- ค้นหาและกรองข้าม 6 มิติ
   283→- Cascading Dropdown ตำแหน่ง (อาคาร → ชั้น → แผนก → สถานที่)
   284→- Barcode/QR Scanner กรอก Serial และ MAC Address
   285→- Auto-fill ยี่ห้อ/ประเภท จาก Model ที่บันทึกไว้
   286→- บันทึกมิเตอร์ตั้งต้นพร้อมกันเมื่อเพิ่มเครื่องพิมพ์
   287→- Bulk Edit เลือกหลายรายการแก้ไขพร้อมกัน
   288→- Export: CSV / Excel / PDF / Print
   289→- Import จากไฟล์ Excel พร้อมนำเข้าประวัติมิเตอร์ย้อนหลัง
   290→- **พิมพ์สติกเกอร์ QR Code ขนาด 75.2 × 36 mm (หรือขนาดที่กำหนดเอง)**
   291→
   292→### 5.3 ย้ายตำแหน่ง (Location Transfer)
   293→- ค้นหาด้วย Asset No. หรือ Serial No.
   294→- รองรับย้ายข้าม Site + ออก AssetSiteCode ใหม่อัตโนมัติ
   295→- บังคับจดมิเตอร์ก่อนย้าย (สำหรับอุปกรณ์ที่ตั้งค่าไว้)
   296→- บันทึก Location_History ทุกครั้ง
   297→- ใช้ทะเบียน Site เดิมเมื่อย้ายกลับ Site ที่เคยอยู่
   298→
   299→### 5.4 จดมิเตอร์ (Meter Reading)
   300→- กล่องค้นหาด่วน: พิมพ์ Serial 4-5 ตัวท้าย / Asset No. / รุ่น / แผนก
   301→- คีย์บอร์ด-driven: ↑↓ เลือกเครื่อง, Enter กรอกเลข, Enter บันทึก
   302→- Log รายการที่คีย์ล่าสุดแสดงด้านบนตาราง
   303→- Progress Bar: คีย์แล้ว X / ทั้งหมด Y (เหลือ Z เครื่อง)
   304→- รองรับมิเตอร์แบบรวม (TOTAL) และแยกขาวดำ/สี (BW_COLOR)
   305→- Export ใบจดมิเตอร์เฉพาะเครื่องที่ยังไม่ได้จด
   306→
   307→### 5.5 วิเคราะห์การใช้กระดาษ (Paper Analytics)

   362→### 6.2 Multi-template Library
   363→
   364→#### โครงสร้าง JSON Template
   365→```javascript
   366→{
   367→  id: 'default',              // unique id ('default' ลบไม่ได้)
   368→  name: 'เทมเพลตเริ่มต้น',     // ชื่อที่แสดง
   369→  isDefault: true,            // ลบไม่ได้
   370→  canvas: {
   371→    width: 75.2,              // ความกว้าง mm
   372→    height: 36,               // ความสูง mm
   373→    unit: 'mm'
   374→  },
   375→  overflow: 'clip',           // 'clip' (ตัด) | 'visible' (เกินขอบ)
   376→  elements: [
   377→    {
   378→      id: 'logo',
   379→      type: 'text' | 'image' | 'qr' | 'rect',
   380→      x: 1, y: 1,             // ตำแหน่ง (mm)
   381→      width: 11, height: 11,  // ขนาด (mm)
   382→      opacity: 1,             // 0-1 (ความโปร่งใส)
   383→      zIndex: 1,              // ลำดับชั้น
   384→      rotation: 0,            // องศา (optional)
   385→      // type-specific:
   386→      // text: fontSize, fontWeight, color, align, content, border, background
   387→      // image: source, objectFit
   388→      // qr: source
   389→      // rect: background, border
   390→    }
   391→    // ... 17 elements ใน default
   392→  ]
   393→}
   394→```

   396→#### การจัดการ Library (UI ใน Settings → 🎨 สติกเกอร์)
   397→- **📋 Template List** — แสดงทุก template พร้อม badges:
   398→  - ⭐ = template ที่ใช้งานอยู่ (active)
   399→  - ✏️ = template ที่กำลังแก้ไข
   400→  - 📄 = template ปกติ
   401→  - `[เริ่มต้น]` = default template (ลบไม่ได้)
   402→  - `[ใช้อยู่]` = active template
   403→- **➕ สร้างเทมเพลตใหม่** — เริ่มจาก default
   404→- **📋 ทำสำเนา** — duplicate template ที่มีอยู่
   405→- **⭐ ตั้งเป็นที่ใช้งาน** — set as active
   406→- **🗑️ ลบ** — ลบ template (ยกเว้น default + active)
   407→- **✏️ แก้ไข** — เปิดใน editor

   518→### 6.6 การพิมพ์สติกเกอร์
   519→
   520→#### Single Print (ทีละใบ)
   521→1. คลิกปุ่ม "สติกเกอร์" ในแถวอุปกรณ์
   522→2. โหลด settings + active template (ถ้ายังไม่ได้โหลด)
   523→3. `renderDeviceStickerSingle()` — ใช้ active template หรือ default
   524→4. `triggerStickerPrint()` — inject `@page size` ตาม template.canvas
   525→5. `window.print()` — พิมพ์ที่ขนาดกระดาษจริง
   526→
   527→#### Bulk Print (หลายใบพร้อมกัน)
   528→1. ติ๊ก checkbox เลือกหลายอุปกรณ์ (สูงสุด 60)
   529→2. คลิก "🖨️ พิมพ์สติกเกอร์ที่เลือก"
   530→3. `renderBulkStickers()` — สร้างสติกเกอร์ทีละใบใน temp div
   531→4. รวม HTML ทั้งหมดเป็น grid
   532→5. `triggerStickerPrint()` — คำนวณ columns อัตโนมัติ:
   533→   ```javascript
   534→   cols = Math.floor(200 / (w + 2))  // A4 width 210 - margin 10
   535→   ```
   536→6. Inject CSS: `grid-template-columns: repeat(cols, w mm)`
   537→7. `window.print()` — พิมพ์หลายใบใน A4

   547→### 6.7 Version Stamp (กัน Cache เก่า)
   548→
   549→**ปัญหา:** Client cache ทำให้ print ไม่ตรงกับ Settings ล่าสุด
   550→
   551→**วิธีแก้:**
   552→1. Backend: `stickerTemplateVersion` field ใน App_Settings
   553→2. `bumpStickerTemplateVersion()` เรียกทุกครั้งที่:
   554→   - saveStickerTemplateEntry
   555→   - deleteStickerTemplate
   556→   - setActiveStickerTemplate
   557→   - updateAppSettings (เมื่อ toggle flag)
   558→3. Client: `stickerSettingsNeedsReload()` ตรวจทุกครั้งที่ print
   559→   - ถ้า > 60 วินาทีหลัง print ล่าสุด → reload
   560→   - ถ้า version เปลี่ยน → reload
   561→4. Manual refresh: ปุ่ม "🔄 รีเฟรชการตั้งค่า" ใน bulk-sticker-bar
   562→
   563→### 6.8 Rollback (3 ระดับ)
   564→- **Level 1**: ปิด toggle "เปิดใช้งานเทมเพลต" → ใช้ default template
   565→- **Level 2**: ลบ template ที่ไม่ใช้ใน library
   566→- **Level 3**: git revert commit

   692→## 9. Performance และ Cache
   693→
   694→### 3 ชั้น Cache
   695→
   696→#### ชั้นที่ 1: Request Cache (`_rc`)
   697→- ใช้ตลอดอายุ 1 request (doGet/doPost)
   698→- ป้องกันอ่าน Sheet ซ้ำใน request เดียวกัน
   699→- `rcClear()` เรียกตอนเริ่ม doGet
   700→
   701→```javascript
   702→var _rc = {};
   703→function rcLazy(key, fn) {
   704→  return _rc.hasOwnProperty(key) ? _rc[key] : (_rc[key] = fn());
   705→}
   706→```
   707→
   708→#### ชั้นที่ 2: Script Cache (CacheService)
   709→- TTL ต่างกันตามประเภท:
   710→  - Dashboard: 180 วินาที
   711→  - App Settings: 300 วินาที
   712→  - Auth: 60 วินาที
   713→  - Site Attributes: 300 วินาที
   714→
   715→#### ชั้นที่ 3: Client Cache (browser)
   716→- `state.stickerSettingsLoaded` — โหลด settings ครั้งเดียว
   717→- `state.activeStickerTemplate` — เก็บ template ที่โหลดแล้ว
   718→- `stickerTemplateVersion` — version stamp สำหรับ invalidate
   719→- Cache window: 60 วินาที (performance)
   720→
   721→### การ Optimize
   722→- **Batch operations** — `batchUpdateRow()` ทำ 1 API call ต่อหลายคอลัมน์
   723→- **LockService** — กัน concurrent write conflict ตอน add/transfer device
   724→- **Header alias mapping** — รองรับชื่อคอลัมน์ไทย/อังกฤษ 10+ รูปแบบ
   725→
   726→### Quota ที่ต้องระวัง
   727→- `UrlFetchApp`: 20,000 calls/day (QR codes ผ่าน quickchart.io)
   728→- `MailApp`: 100 emails/day
   729→- Execution timeout: 6 นาทีต่อ request
